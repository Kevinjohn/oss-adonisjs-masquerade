# M4 requirement-to-evidence ledger

**Status:** M4 verification is complete for the current release candidate. M0–M3 evidence is recorded in [M3-RESULT.md](https://github.com/Kevinjohn/oss-adonisjs-masquerade/blob/7e0940e/M3-RESULT.md). After the async migration correction, `pnpm test` passed 162 SQLite tests, `pnpm test:pg` passed 158 PostgreSQL 16 tests (server stopped cleanly), and build, typecheck and two built-export checks passed. Six configure/migration cases pass; floor/latest generated scaffolds compile; the native credential case passes 1/1. All four packed floor/latest × SQLite/PostgreSQL 16.15 cells passed, for 72 functional, report and credential executions. Exact versions and artifact identity are recorded below. This verification does not imply publication.

**Authority and scope:** The accepted `DEVELOPMENT-PLAN.md` wins where it narrows SPEC/PRD. v1 is native session only; opaque access-token adapter is v1.1 and JWT is out. The Account Kit adapter and managed-route blocker are accepted v1.2 scope and are implemented in the open PR stack. The pinned GitHub release artifact `adonisjs-account-kit@0.1.3` passed all 16 floor/latest SQLite/PostgreSQL cells across both strategies and session-management settings on 27 October 2026; `0.1.1` passed the same matrix on 22 October 2026 and is no longer declared. Public registry publication is a separate distribution step, not an integration acceptance gate. Core retains the native `securityStamp`/`inspectAccount` contract and no Account Kit dependency. Cut JSON:API, package i18n, and 4x2x2 consumer matrix. FR-09 uses route-report release gate; FR-14 owner-bound revision.nonce + report/enforce; FR-21/22 SHA-256 stamps; FR-30 emit-and-forget; indeterminate commit 503 + transition ID + status recovery. Consumer target is one native-session packed consumer at floor/latest on SQLite/PostgreSQL.

Legend: evidence names a concrete current test case; statements explicitly identified as optional are integration-depth opportunities, not uncovered acceptance requirements. M3 outcomes are recorded in [M3-RESULT.md](https://github.com/Kevinjohn/oss-adonisjs-masquerade/blob/7e0940e/M3-RESULT.md). Documentation obligations are linked to user guides; link checks do not establish semantic completeness.
